# Stage E-P v3b — stage E-P with the v3b searcher and judges

Built 2026-11-14 on the operator's instruction: *"a routine like E-P (that doesn't
trade), named ep v3b, and improve the searcher and judger based on this analysis. The
goal is to see if it predicts better than the current e-p."* The analysis is the review
of us-panel.v3 in `research/analyses/us-panel-v3-information/`. It asks one question:
**do the v3b prompts predict the earnings reaction better than stage E-P's?** The
models, the sweep, the cap, the packs format and the selection rule are stage E-P's, so
the two prompts are the only variables.

This file is an overlay on an overlay: follow `.claude/skills/earnings-edge-panel/SKILL.md`
step by step (which itself follows `.claude/skills/earnings-edge-hunt/SKILL.md`), and do
differently only what the table below says. Read `CLAUDE.md`, then the stage E skill,
then the stage E-P skill, then come back here.

## Check the searchers' output

After each searcher returns, check that its hunt has the `expectations` and `next_guide`
blocks and an `evidence_type` on its items. A hunt without them was written on the old
contract (usually the fallback lost the addendum): relaunch it once in a later turn with
the v3b body pasted in. If it fails again, keep it, and name it in the run log and the
note as `v3b fields missing`, because it judges as a stage E-P pack.

## 5p. Scoring the panel: two calls

```bash
python3 researcher_us/scripts/panel_score.py --run <RUN>/edge-panel-v3b --dry-run --stage "E-P v3b (E-P scale)"
mv <RUN>/edge-panel-v3b/edge-scores-panel.json <RUN>/edge-panel-v3b/edge-scores-panel-epscale.json
python3 researcher_us/scripts/panel_score.py --run <RUN>/edge-panel-v3b --history researcher_us/analysis/panel-history-v3b.json --stage "E-P v3b"
```

The first reads each v3b judge against stage E-P's judges' live range and writes
nothing to any history; it is kept so the two stages can be read on one scale. The
second is the stage's own result: each v3b judge against its own history
(`researcher_us/analysis/panel-history-v3b.json`, seeded on 2026-11-14 with a frozen copy
of stage E-P's, so the seed sets the scale until the v3b judges have about ten run days
of their own), and it appends the day's sizes to that file. `edge-scores-panel.json` is
the second file. The selection rule is stage E-P's (`panel_pct` >= 80, all four judges),
and `expected_return_pct` is stage E-P's calibration curve, not one fitted on v3b: say
so in the note.

## The note

`<RUN>/edge-panel-v3b/edge-note.md`, stage E-P's note with three changes:

1. Line 1: **"this is stage E-P v3b: Opus 5.5 searchers and four blind judges on the
   v3b prompts, no orders"**, which judges ran, and that one day is an anecdote.
2. The panel table gets two more columns: `panel_pct` on stage E-P's scale (from
   `edge-scores-panel-epscale.json`) and the judges' mean three-part forecast,
   p_clears_real_bar and the most common guide_direction.
3. A comparison block, if stage E-P's `<RUN>/edge-panel/edge-scores-panel.json` exists
   by then: names both ranked, the overlap of the two selected sets, the Spearman ρ
   between the two `panel_pct_signed` columns, and per name where the two panels
   disagree on side or on selection, one line each. If E-P has not finished, say so; do
   not wait.

**The closing chat reply** starts with the verbatim output of
`python3 scripts/score_report.py --run <RUN>/edge-panel-v3b --label "Stage E-P v3b (searcher)"`,
then the same command on `<RUN>/edge-panel` with `--label "Stage E-P (searcher)"` if
those files exist, then the panel table from the second `panel_score.py` call, then the
comparison block. Finish with `python3 scripts/update_index.py` and
`scripts/publish.sh "edge hunt panel v3b: <what> for <YYYY-MM-DD>"`. It pushes to `main`.

## Resolve

`edge_resolve.py --run <RUN>/edge-panel-v3b` ranks the searcher's key and
`spearman_panel` exactly as for stage E-P. The comparison with stage E-P is
`python3 researcher_us/scripts/v3b_compare.py`, pooled over every day both stages ran,
on the names both ranked, against the pre-registration in
`research/analyses/us-panel-v3-information/PREREGISTRATION.md`. It reads nothing before
20 run days. Never judge v3b on one day.

This is research, not investment advice.
